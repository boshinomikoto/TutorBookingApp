# Вимоги до версії v1.0

Межі v1.0 — за Product Vision з ЛР №1: система для одного репетитора,
без мережі, без кількох репетиторів в одному кабінеті, без автоматичних
нагадувань, онлайн-оплати чи відеозв'язку. Актор — один, **Репетитор**;
учень у системі не авторизується, це лише дані.

## Функціональні вимоги

| ID | Вимога | Критерій приймання |
|---|---|---|
| FR-01 | Система повинна дозволяти Репетитору зареєструвати нового учня з обов'язковим повним ім'ям та необов'язковими телефоном і нотатками. | AC-01: після збереження учень з'являється у списку з указаними даними. |
| FR-02 | Система повинна дозволяти Репетитору редагувати дані вже зареєстрованого учня (ім'я, телефон, нотатки). | AC-02: змінені дані відображаються у картці учня одразу після збереження. |
| FR-03 | Система повинна дозволяти Репетитору створити новий запис на консультацію для обраного учня з датою/часом початку та тривалістю. | AC-03: новий запис з'являється в розкладі зі статусом Scheduled. |
| FR-04 | Система повинна відхиляти створення запису, якщо його інтервал `[Start, Start+Duration)` перетинається з інтервалом будь-якого іншого запису зі статусом, відмінним від Cancelled. | AC-04: при спробі створити такий запис система повідомляє про перетин, запис не зберігається. |
| FR-05 | Система повинна дозволяти Репетитору скасувати запис зі статусом Scheduled. | AC-05: статус змінюється на Cancelled; такий запис більше не враховується при перевірці перетину часу. |
| FR-06 | Система повинна дозволяти Репетитору позначити запис як проведений (Completed) лише один раз і лише за умови вказаної теми заняття. | AC-06: повторна спроба або спроба без теми відхиляється; з темою — статус змінюється на Completed. |
| FR-07 | Система повинна дозволяти Репетитору переглянути історію занять обраного учня, відсортовану за датою, з фільтром за статусом. | AC-07: список відображає записи учня хронологічно; фільтр звужує список коректно. |
| FR-08 | Система повинна дозволяти Репетитору переглянути розклад консультацій на обраний день або тиждень. | AC-08: відображаються всі записи обраного періоду з їхніми статусами. |

## Нефункціональні вимоги

| ID | Вимога | Критерій приймання |
|---|---|---|
| NFR-01 | Система розрахована на одного користувача (Репетитора), без мережевого доступу — локальний файл SQLite. | Усі операції виконуються без підключення до мережі; файл бази зберігається поруч зі скомпільованою програмою. |
| NFR-02 | Відгук на типові операції (створення запису, перегляд розкладу/історії) — не довше 300 мс при локальному обсязі даних (до кількох тисяч записів). | Вимірюваний час від введення команди до відображення результату ≤300 мс на референсному наборі даних. Перевіряється в ЛР №4. |
| NFR-03 | Історія занять зберігається необмежено за часом, без автоматичного видалення. | Записи зі статусом Completed/Cancelled лишаються доступними в історії незалежно від дати. |

## Не входить до v1.0

Онлайн-оплата, автоматичні нагадування, вбудований відеозв'язок,
синхронізація із зовнішніми календарями, підтримка кількох репетиторів в
одному кабінеті — межі погоджені ще в ЛР №1 і тут не розширюються.
