# Use Case Diagram і специфікації

## Діаграма варіантів використання

Один зовнішній актор — **Репетитор** — і сім варіантів використання v1.0.
UC3 включає (`include`) технічну перевірку «Перевірити перетин часу».

![Use Case Diagram](images/use-case.svg)

| ID | Назва | Деталізовано ким |
|---|---|---|
| UC1 | Зареєструвати учня | Максим — повна специфікація + Activity Diagram |
| UC2 | Редагувати дані учня | коротко нижче |
| UC3 | Створити запис на консультацію | Вадим — повна специфікація + Activity Diagram |
| UC4 | Скасувати запис | коротко нижче |
| UC5 | Позначити заняття проведеним | Олександр — повна специфікація + Activity Diagram |
| UC6 | Переглянути історію занять учня | коротко нижче |
| UC7 | Переглянути розклад на день/тиждень | коротко нижче |

## UC-01 «Зареєструвати учня» (Максим)

| Поле | Значення |
|---|---|
| ID і назва | UC-01 «Зареєструвати учня» |
| Мета | Додати нового учня до системи. |
| Основний актор | Репетитор |
| Тригер | Репетитор хоче додати нового учня. |
| Передумови | Немає — це перший запис про учня. |
| Основний сценарій | 1. Репетитор відкриває форму додавання учня.<br>2. Вводить повне ім'я (обов'язково), телефон і нотатки (необов'язково).<br>3. Система перевіряє, що повне ім'я вказано.<br>4. Система зберігає нового учня.<br>5. Система показує учня у списку. |
| Альтернативний сценарій | A1. На кроці 3 ім'я не вказано — система повідомляє про обов'язкове поле, учень не зберігається. |
| Постумови | Успіх: учень доданий до списку. Помилка: список учнів не змінено. |
| Пов'язані вимоги | FR-01 |
| Критерії приймання | AC-01 |

Activity Diagram — `model/activity-uc1.md`.

## UC-02 «Редагувати дані учня» (стисло)

Репетитор обирає учня зі списку, змінює ім'я/телефон/нотатки, система
зберігає оновлені дані. Обов'язковість повного імені перевіряється так
само, як у UC1. Пов'язана вимога — FR-02 (AC-02).

---

## UC-03 «Створити запис на консультацію» (Вадим)

| Поле | Значення |
|---|---|
| ID і назва | UC-03 «Створити запис на консультацію» |
| Мета | Додати новий запис на консультацію для обраного учня, не допустивши перетину з іншими активними записами. |
| Основний актор | Репетитор |
| Тригер | Репетитор обрав учня і вводить нову консультацію. |
| Передумови | Учень уже зареєстрований у системі (UC1 виконано). |
| Основний сценарій | 1. Репетитор обирає учня зі списку.<br>2. Вводить дату, час початку та тривалість консультації.<br>3. Система перевіряє перетин часу з іншими активними (не Cancelled) записами — `include` «Перевірити перетин часу».<br>4. Якщо перетину немає, система зберігає запис зі статусом Scheduled.<br>5. Система повідомляє про успішне створення. |
| Альтернативний сценарій | A1. На кроці 3 знайдено перетин — система відхиляє запис і повідомляє про конфліктний інтервал. |
| Постумови | Успіх: новий запис зі статусом Scheduled доданий до розкладу. Помилка: розклад не змінено. |
| Пов'язані вимоги | FR-03, FR-04 |
| Критерії приймання | AC-03, AC-04 |
| Included Use Case | «Перевірити перетин часу» — перевіряє перетин нового інтервалу з інтервалами всіх активних записів цього репетитора; викликається з UC3 на кроці 3. |

Activity Diagram — `model/activity-uc3.md`.

## UC-04 «Скасувати запис» (стисло)

Репетитор обирає запис зі статусом Scheduled і скасовує його. Статус
змінюється на Cancelled; такий запис більше не враховується при перевірці
перетину часу (див. State Machine Diagram у `docs/design.md`). Пов'язана
вимога — FR-05 (AC-05).

---

## UC-05 «Позначити заняття проведеним» (Олександр)

| Поле | Значення |
|---|---|
| ID і назва | UC-05 «Позначити заняття проведеним» |
| Мета | Зафіксувати, що консультація відбулась, разом із темою заняття. |
| Основний актор | Репетитор |
| Тригер | Репетитор хоче закрити запис як проведений. |
| Передумови | Запис існує і має статус Scheduled. |
| Основний сценарій | 1. Репетитор обирає запис зі статусом Scheduled.<br>2. Вводить тему заняття (обов'язково) і, за бажанням, нотатку.<br>3. Система перевіряє, що запис ще не Completed і що тема вказана.<br>4. Система змінює статус на Completed і зберігає тему/нотатку.<br>5. Система повідомляє про успішне завершення. |
| Альтернативний сценарій | A1. На кроці 3 запис уже Completed — система відхиляє повторну спробу.<br>A2. На кроці 3 тема не вказана — система повідомляє про обов'язкове поле. |
| Постумови | Успіх: статус запису Completed з темою. Помилка: статус не змінено. |
| Пов'язані вимоги | FR-06 |
| Критерії приймання | AC-06 |

Activity Diagram — `model/activity-uc5.md`.

---

## UC-06 «Переглянути історію занять учня» (стисло)

Репетитор обирає учня, система показує всі його записи, відсортовані за
датою, з можливістю фільтра за статусом (Scheduled/Completed/Cancelled).
Пов'язана вимога — FR-07 (AC-07).

## UC-07 «Переглянути розклад на день/тиждень» (стисло)

Репетитор обирає період (день або тиждень), система показує всі записи
цього періоду з їхніми статусами. Пов'язана вимога — FR-08 (AC-08).
